### Security Audit

| # | Severity | File | Issue | Recommendation |
|---|----------|------|-------|----------------|
| 1 | Critical | `UploadPhotosAction:70`, `InterventionImageProcessor:45` | Path traversal via unsanitized client filename in variant paths | Use photo UUID for variant paths, `basename()` on stored filename |
| 2 | Critical | `PhpExifExtractor.php:101–110` | Temp file never deleted — sensitive data on disk | `register_shutdown_function` or try/finally unlink |
| 3 | High | `routes/api.php:42–46` | All photos publicly enumerable without auth | Confirm design intent or add auth; gate `filename` field behind ownership |
| 4 | High | `PhpExifExtractor.php:107` | Client-supplied MIME propagated to reconstructed file | Use `$file->getMimeType()` (server-detected) |
| 5 | High | `PhpExifExtractor.php:98`, `DiskPhotoStorage` | Client extension used unsanitized — JPEG stored as `.php` | Allowlist extensions: `['jpg','jpeg','png','webp']` |
| 6 | High | `InterventionImageProcessor:36`, `PhpExifExtractor:95` | No dimension check before decode — decompression bomb | Check against `config('photogallery.images.max_dimension')` after decode |
| 7 | Medium | `ProcessPhoto.php:52` | Raw exception message with file paths returned to owner | Log full error, store generic user-facing message |
| 8 | Medium | `UploadPhotosAction.php:53–94` | Bus::batch inside transaction — race condition | Move dispatch after transaction or use `->afterCommit()` |
| 9 | Medium | `StorePhotosRequest.php:46` | `new_tags` accepts unrestricted characters including HTML | Add character-class regex validation |
| 10 | Low | `PhpExifExtractor.php:26` | `@exif_read_data` suppresses warnings unnecessarily | Remove `@`, rely on try/catch |
| 11 | Low | `PhotoData.php:93–100` | Unsigned URL fallback swallows all exceptions silently | Narrow catch, log before fallback |
